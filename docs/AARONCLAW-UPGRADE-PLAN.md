## 四、改造方案(按优先级)

### Phase 1: 核心体验 (必须做)

#### 1.1 错误处理全面升级
**问题**: Agent 中途报错卡死，不会自动恢复
**现状**: llm.ts 只有简单 try/catch，没有按错误类型分类
**方案**:
- 新建 `retry-engine.ts` (已完成)
- 按 HTTP 状态码精确分类: 429/5xx=重试, 401/403=不重试
- 指数退避: 2s → 4s → 8s → 30s(max)
- Doom Loop 检测: 同一错误连续3次停止
- Provider 降级链: 主模型失败自动切备用
**工作量**: 1天 (retry-engine.ts 已写好，需集成)

#### 1.2 开发模式 (Plan/Code/Auto/Compose)
**问题**: 只有默认模式，没有区分
**方案**:
- UI: 聊天输入框加模式切换 [Plan|Code|Auto|Compose]
- Plan: 只读工具，输出方案后等确认
- Code: 全部工具，逐步确认 (当前默认)
- Auto: 全部工具，不需确认
- Compose: 分阶段执行 (spec→plan→code→test→review→commit)
**工作量**: 2-3天
**改的文件**: orchestrator.ts, main.ts, ChatPage.tsx

#### 1.3 上下文管理 (Compaction + Checkpoint)
**问题**: 长对话直接溢出崩溃
**方案**:
- 溢出检测: 每次 API 响应后检查 token 用量
- 压力等级: 0(<50%) / 1(50-70%) / 2(70-85%) / 3(>85%触发压缩)
- 自动压缩: 超80%用 LLM 将旧对话摘要
- Checkpoint: 定期保存会话状态到文件
- 恢复时: 从 checkpoint + 记忆重建上下文
**工作量**: 3-4天
**参考**: MiMo Code compaction.ts + checkpoint.ts

#### 1.4 Goal + Judge (防过早停止)
**问题**: Agent 经常"觉得自己做完了"
**方案**:
- 系统提示词加 stop-condition 检查
- 对话结束前用独立 LLM 调用评估完成度
- 返回 {ok, reason} 决定是否继续
- 最多重新评估 3 次
**工作量**: 0.5天
**参考**: MiMo Code goal.ts

#### 1.5 代码能力补全
**问题**: 缺专业开发工具
**方案**:
- `ac_patch_file` — 增量修改文件 (不重写)
- `ac_git` — commit/push/pull/status/diff/log
- `ac_build` — 自动检测项目类型并构建
- `ac_test` — 自动检测并运行测试
**工作量**: 2天
**参考**: Skales Codework

### Phase 2: 智能进化 (应该做)

#### 2.1 Background Goals (后台执行)
**问题**: 关窗口就停，不能同时做多件事
**方案**:
- goals 表: id, task, status, steps, progress, scheduled_at
- 后台执行引擎: 主进程独立，不依赖渲染进程
- UI: 目标列表+进度卡片+决策弹窗
- 完成后通知(桌面通知+声音)
- 支持多目标并行+定时重复
**工作量**: 4-5天
**参考**: Skales Background Goals

#### 2.2 Dream 记忆整理
**问题**: 记忆只增不减，会膨胀
**方案**:
- 每周自动执行: 扫描记忆→LLM评估→清理过时→合并重复
- 手动触发: /dream
- Dream Diary: 记录整理过程
**工作量**: 2天
**参考**: MiMo Code /dream + Skales Dreaming

#### 2.3 行为学习升级
**问题**: 现有学习只有基础的情绪检测
**方案**:
- instinct(本能) + 置信度评分
- 项目级 vs 全局级隔离
- 会话结束时自动提取关键信息
- 学到的规则有"置信度"，用多了才确认
**工作量**: 2天
**参考**: ECC continuous-learning-v2

#### 2.4 多Agent协作升级
**问题**: 群聊是"讨论"模式，不是"执行"模式
**方案**:
- Agent 组织架构: 部门/角色/上下级
- 任务自动路由: 根据内容分配给最合适的 Agent
- Agent 间任务传递: A做不了→自动转给B→B完成后回报
- 强模型规划+快模型执行策略
**工作量**: 3-4天
**参考**: Orkas Commander + Skales Organization

#### 2.5 Per-Agent 配置
**问题**: 所有Agent共用全局模型和工具
**方案**:
- 每个 Agent 可配置独立模型
- 每个 Agent 可配置工具白名单
- 代码任务用强模型，聊天用快模型
**工作量**: 1天

### Phase 3: 交互升级 (值得做)

#### 3.1 Voice TTS (语音回复)
**问题**: 有语音输入，没有语音回复
**方案**:
- 每条回复加 🔊 按钮
- "自动朗读"开关
- TTS: 设备语音(免费) + Edge TTS(免费，音质好) + OpenAI TTS(可选)
- 免提模式: 说完→思考→语音回复
**工作量**: 2天
**参考**: Skales Voice

#### 3.2 权限分级
**问题**: 只有黑名单，没有分级
**方案**:
- allow/deny/ask 三级
- 通配符匹配 (*.env, /system32/*)
- once/always 授权
- .env 文件读取需要确认
**工作量**: 1天
**参考**: MiMo Code Permission

#### 3.3 知识技能扩展
**问题**: 只有内置技能，不能导入外部
**方案**:
- 兼容 SKILL.md 格式 (superpowers/ECC/Cursor)
- 从 GitHub URL 导入
- 社区技能市场
- 会话结束时自动提取新技能
**工作量**: 2天
**参考**: Skales Agent Skills

#### 3.4 模板库
**问题**: 只有 workflow_template
**方案**:
- 每个 Agent 5-10 个常用场景模板
- 用户自定义模板
- 模板分享/导入
**工作量**: 1天
**参考**: Skales Templates
